# Implementation Plan

## Overview
このドキュメントは、cfgctl diff コマンドに ANSI カラーコードによる色分け表示を実装するための詳細なタスク一覧です。各タスクは段階的に進め、既存の機能との互換性を保ちながら、ユーザーフレンドリーな差分表示を実現します。

---

- [x] 1. ANSI カラーコード基盤の実装
- [x] 1.1 カラーコード定数と色出力の基盤を整備
  - ANSI カラーコード定数（赤、緑、黄、シアン、リセット）を定義
  - ターミナル判定ロジック（isatty）を実装し、出力がターミナルかファイルかを判定
  - golang.org/x/term の IsTerminal() を利用して標準出力がターミナルであるか確認
  - 色出力の有効化/無効化を制御する内部状態管理機構を構築
  - _Requirements: 4.1, 6.1, 6.2_

- [x] 1.2 --color フラグの定義と解析機能を実装
  - diff.go に --color フラグ定義を追加（デフォルト: "auto"）
  - "auto"、"always"、"never" の3つの値をサポート
  - フラグ値の検証ロジック（不正な値のエラーハンドリング）
  - フラグ値に基づいて色出力の有効化判定関数を実装
  - _Requirements: 4.2, 4.3, 4.4_

- [x] 1.3 差分行の色付け関数群を実装
  - 削除行を赤色で表示する関数を実装
  - 追加行を緑色で表示する関数を実装
  - ヘッダー行（---、+++、@@）をシアンで表示する関数を実装
  - ANSI リセットコードを確実に追加し、色が後の行に影響しないようにする
  - テスト用に各関数の入出力を検証
  - _Requirements: 1.1, 1.2, 1.3_

---

- [x] 2. 2ステージ diff 出力への色付け統合
- [x] 2.1 displayParameterStoreDiffWithTypes() に色付けを統合
  - 削除パラメータ出力時（"- key"）に赤色を適用
  - 追加パラメータ出力時（"+ key"）に緑色を適用
  - ヘッダー行（"---"、"+++"、"@@"）にシアン色を適用
  - マスク文字列（***masked secret***）を削除/追加時の対応色で表示
  - 既存の keys-only モードおよび show-secrets オプションとの互換性確保
  - _Requirements: 1.1, 1.2, 1.4, 5.1, 5.2_

- [x] 2.2 2ステージ diff の差分値出力に色付けを適用
  - JSON 差分出力（FormatJSONDiffOutput など）の削除/追加/変更行に色を付与
  - ネストされた JSON 属性でもインデント構造を保ちながら色分けを維持
  - JSON パス情報行をシアンで表示し、値行を差分タイプの色で表示
  - _Requirements: 3.1, 3.2, 3.3_

- [x] 2.3 2ステージ diff 出力の統合テスト
  - 削除パラメータの赤色表示を確認
  - 追加パラメータの緑色表示を確認
  - --color=never で色が無効化されることを確認
  - --color=always で強制的に色付けされることを確認
  - パイプ出力時に自動的に色が無効化されることを確認（--color=auto）
  - _Requirements: 4.1, 4.4_

---

- [x] 3. マルチステージ diff 出力への色付け統合
- [x] 3.1 displayMultiStageDiffWithTypes() のテーブル形式に色付けを適加
  - テーブルヘッダー行と区切り線を表示（既存）
  - ステージ間で異なる値を検出する機構を実装
  - 異なる値を黄色またはハイライト色で表示（または背景色を検討、ただし初期実装は簡潔に）
  - 同一値はデフォルト色で表示
  - パラメータが一部ステージにのみ存在する場合、存在しないセルを灰色またはハイライトで表示
  - _Requirements: 2.2, 2.3, 2.4_

- [x] 3.2 マルチステージ diff でのキーのみモードの対応
  - --keys-only モードで表示されるパラメータ名が色付けされないことを確認（デフォルト）
  - または、パラメータの存在ステージ数に基づいた色分け表示を検討
  - _Requirements: 2.1_

- [x] 3.3 マルチステージ diff の統合テスト
  - 3ステージ以上の比較で異なる値が色付きで表示されることを確認
  - 同一値がデフォルト色で表示されることを確認
  - パラメータの欠落セルが視覚的に区別されることを確認
  - --color フラグによる制御が機能することを確認
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

---

- [x] 4. セキュリティと特殊ケースの対応
- [x] 4.1 SecureString パラメータでの色付け処理
  - --show-secrets フラグなし時に マスク文字列を対応する色で表示（削除は赤、追加は緑など）
  - --show-secrets フラグ付き時に実際の秘密値を対応する色で表示
  - 色付けによる秘密値の漏洩がないことを確認
  - _Requirements: 5.1, 5.2, 5.3_

- [x] 4.2 ANSI コード注入対策の実装
  - ユーザー入力（パラメータ名・値）に含まれる ANSI コードをエスケープ
  - パラメータ値内に `\x1b` が含まれている場合の処理を定義
  - ターミナルインジェクション攻撃を防止する機構を実装
  - _Requirements: 4.1_

- [x] 4.3 セキュリティ対応のテスト
  - 秘密値を含むパラメータの色付き表示で秘密値が漏洩していないことを確認
  - ANSI コード文字列を含むパラメータ名・値の表示が正常であることを確認
  - _Requirements: 5.1, 5.2, 5.3_

---

- [x] 5. ターミナル互換性と動作確認
- [x] 5.1 異なるターミナル環境での動作確認
  - macOS Terminal での色表示確認
  - macOS iTerm2 での色表示確認
  - Linux bash（gnome-terminal、xterm など）での色表示確認
  - Windows Terminal（WSL2）での色表示確認
  - Windows Git Bash での色表示確認（オプション）
  - _Requirements: 6.1_

- [x] 5.2 ANSI カラーコード標準化の確認
  - 赤（code 31）、緑（code 32）、黄（code 33）、シアン（code 36）が標準的に使用されていることを確認
  - リセットコード（code 0）が正常に機能していることを確認
  - 太字属性（code 1）の使用有無を検討・実装（オプション）
  - _Requirements: 6.2_

- [x] 5.3 古いターミナル環境への対応確認
  - 非標準ターミナルや ANSI をサポートしていない環境では色が無効化されることを確認
  - isatty() が false を返す環境での動作が正常であることを確認
  - _Requirements: 6.3_

- [x] 6. エッジケースとエラーハンドリング

  - _Requirements: 1.1_

- [x] 6.2 大量パラメータ出力の性能確認

  - _Requirements: 1.1_

- [x] 6.3 不正な --color フラグ値のハンドリング

  - Cobra フレームワークのフラグ検証が機能していることを確認
  - _Requirements: 4.2_
